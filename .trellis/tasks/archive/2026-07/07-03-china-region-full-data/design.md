# 全国完整行政区划数据技术设计

## Architecture

本任务把 `packages/data` 从 MVP 手写样本升级为可复现生成的全国行政区划数据包。核心原则是：

- 源数据和生成脚本分离，避免在 `packages/data/src/index.ts` 手写大数组。
- committed 产物可离线使用，运行时不依赖实时网络接口。
- 数据层提供查询和校验能力；`packages/core` 提供通用类型、搜索、路径结果；`packages/taro` 只做 adapter 状态和选择路径映射。

## Data Scope

第一版中国大陆覆盖四级：

1. 省级：省、自治区、直辖市、特别行政区等。
2. 地级：地级市、地区、自治州、盟等。
3. 县级：市辖区、县、自治县、县级市、旗、自治旗、林区、特区等。
4. 乡级：街道、镇、乡、民族乡、苏木、民族苏木、区公所等。

第一版包含港澳台。港澳台的行政层级、编码体系和可公开获取的细分粒度不完全等同大陆四级，因此按特殊地区兼容模型接入：

- 香港、澳门可作为特别行政区省级节点，下面接入可获取的区级 / 分区级记录。
- 台湾可作为省级或地区级根节点，下面接入可获取的县市、乡镇市区等记录。
- 港澳台路径允许可变深度和地区专属层级名称，记录必须标注 `地区口径` 和 `来源`。
- 港澳台不强行补齐大陆四级，也不纳入村 / 社区 / 居委会第五级范围。

第一版不覆盖村 / 社区 / 居委会第五级。第五级属于更大规模的数据和统计口径，需要单独设计分片、懒加载、包体积预算和更新机制。

## Source Strategy

优先使用官方公开源，第三方整理库作为备选：

- 民政部 / 国家地名信息库作为行政区划代码和地名的首选来源。
- 固定源 URL、抓取日期、数据截止日期、脚本版本和记录数量摘要。
- 如果官方接口需要浏览器环境、反爬限制或不可稳定批量下载，允许第三方整理库作为临时种子。
- 使用第三方整理库时必须记录库名、URL、版本 / commit、许可证、获取时间和数据截止口径。
- 第三方种子必须经过本项目校验，并用官方编码规则、层级数量摘要、重点城市抽样和异常结构抽样兜底。
- 生成产物的元数据要明确区分 `官方源`、`第三方种子` 和 `校验依据`，避免把第三方整理结果伪装成官方原始数据。

生成流程必须输出可审计元数据：

```ts
type 数据来源信息 = {
  来源名称: string
  来源URL: string
  来源类型: "官方源" | "第三方种子"
  许可证?: string
  版本或Commit?: string
  数据截止日期: string
  抓取时间: string
  生成脚本版本: string
  校验依据: readonly string[]
  记录数量: {
    省级: number
    地级: number
    县级: number
    乡级: number
    港澳台: number
  }
}
```

## Data Model

扩展行政区层级类型，并允许特殊地区补充口径：

```ts
type 行政区级别 = "省" | "市" | "区县" | "乡镇街道"
type 地区口径 = "大陆行政区划" | "香港澳门特别行政区" | "台湾地区"
```

保留 `城市.级别` 的现有字段以降低迁移成本，必要时增加更精细的 `行政区类型` 字段描述街道、镇、乡、盟、旗、特别行政区、区、县市、乡镇市区等建制类型。港澳台记录允许 `级别` 使用最接近的兼容层级，同时通过 `行政区类型` 和 `地区口径` 表达真实层级。

四级记录应包含：

- `编码`：大陆省 / 市 / 区县为六位码，乡镇街道为九位码；港澳台使用来源稳定编码或本项目带前缀的稳定编码。
- `名称`：行政区标准名称。
- `级别`：四级之一。
- `行政区类型`：可选，表达街道、镇、乡、特别行政区、区、县市、乡镇市区等地区专属层级名称。
- `父级编码`：省级为空，其余必填。
- `拼音`、`首字母`：用于搜索。
- `地区口径`：区分大陆、港澳、台湾数据口径。
- `路径编码`、`路径名称` 或可由父级索引稳定推导的等价数据。

## Package Boundaries

- `packages/core`
  - 扩展行政区层级类型。
  - `创建行政区选择结果` 支持大陆四级路径、港澳台可变深度路径，并继续接受一到三层路径。
  - 搜索、A-Z 分组和最近访问逻辑保持框架无关。
- `packages/data`
  - 保存原始源数据快照、生成脚本、生成产物和查询 helper。
  - 提供 `内置行政区列表` / `builtInRegions` 的兼容导出。
  - 提供按编码、父级、层级查询的索引。
- `packages/providers`
  - 继续消费 data/core，不复制行政区数据。
- `packages/taro`
  - 适配四级路径、港澳台可变深度路径状态和结构化选择事件。
  - 保留现有三层示例兼容。
- `apps/demo-taro`
  - 增加一个大陆四级路径 demo 和一个港澳台路径 demo。
- `docs`
  - 说明数据范围、来源、版本、更新命令、包体积、限制和第五级排除原因。

## Validation

`validate:data` 必须覆盖：

- 编码唯一。
- 名称非空。
- 层级合法。
- 非省级记录父级存在。
- 大陆父子层级合法，不能跳级。
- 港澳台路径深度和层级名称允许与大陆不同，但父级链必须完整。
- 乡级九位码前六位匹配所属县级编码。
- 港澳台稳定编码不能与大陆编码冲突。
- 省 / 市 / 区县六位码满足基础形态。
- 拼音和首字母存在。
- 热门城市编码存在。
- 特殊结构可通过：直辖市、省直辖县级行政单位、不设区的地级市、盟 / 旗 / 林区 / 特区、港澳台可变深度路径等。

## Compatibility

- 现有三层路径调用仍返回省 / 市 / 区县字段。
- 四级路径新增 `乡镇街道` 字段，并保留 `编码路径` / `名称路径`。
- 港澳台路径不强行填充缺失层级；消费者应优先读 `编码路径` / `名称路径`，再按存在的命名字段或 `行政区类型` 展示。
- `内置城市列表` 可继续作为热门城市和城市搜索的轻量入口，不必等同于完整四级行政区列表。
- 文档必须说明全国完整数据主要通过 `内置行政区列表` 和查询 helper 消费。

## Risks

- 官方源格式和接口可能变化，需要把源快照和转换逻辑纳入版本控制。
- 第三方整理库可能存在许可证、滞后或错漏风险；必须作为备选种子处理，不能替代校验和来源说明。
- 四级数据体量会显著增加，不能把所有数据和索引都塞进主 TypeScript 源文件。
- 拼音生成可能依赖第三方库或自维护字典，需通过测试覆盖多音字和少数民族地名的可接受行为。
- 港澳台数据来源和层级口径不统一；必须通过元数据和文档避免过度承诺。
- 第五级不纳入可能不满足精确到社区的地址场景，必须在文档中明确。

## Rollback

- 保留 MVP 小样本数据的最后提交，可通过 git 回滚数据产物和类型扩展。
- 生成脚本和数据产物分开提交时，若产物有问题，优先修复生成脚本并重新生成，不手工 patch 大数据文件。
